# VertexNote In-App Updates

This is the implementation plan for an in-app update surface that shows the
latest VertexNote release and a concise changelog inside the application.

## User Experience

- Entry point: `Help -> Check for Updates`.
- Dialog states:
  - Checking
  - Up to date
  - Update available
  - Offline/error
- The update dialog should show:
  - current app version
  - latest release version
  - release date
  - concise release notes
  - release assets: Windows installer, Windows portable zip, source archive links
- First implementation should not auto-install. It should open the GitHub release or
  selected asset URL explicitly.

## Release Source

- API endpoint: `https://api.github.com/repos/saitatter/vertex-note/releases/latest`
- Release tag format: `vertex-note-v{semver}`
- Accepted downloadable assets:
  - `vertex-note-v*-windows-x86_64-setup.exe`
  - `vertex-note-v*-windows-x86_64-portable.zip`
- Changelog source:
  - GitHub release body generated by semantic-release.
  - Keep the format aligned with the concise `pylrcget` release notes style.

## Proposed Classes

- `vn::update::ReleaseInfo`
  - `std::string version`
  - `std::string tagName`
  - `std::string publishedAt`
  - `std::string releaseNotes`
  - `std::vector<ReleaseAsset> assets`
- `vn::update::ReleaseAsset`
  - `std::string name`
  - `std::string downloadUrl`
  - `ReleaseAssetKind kind`
- `vn::update::ReleaseChecker`
  - asynchronous fetch of the latest GitHub release
  - maps network/JSON failures to user-visible status
- `vn::update::VersionComparator`
  - strips the `vertex-note-v` prefix
  - compares semantic versions without relying on locale-sensitive parsing
- `QtUpdatePresentationService`
  - Qt presentation layer responsible only for user-visible update actions

## Network Strategy

Current path:

- Windows uses WinHTTP for the release fetch.
- Linux and macOS use Qt Network, keeping the update checker aligned with the Qt
  shell and avoiding runtime GIO/TLS module dependencies.

Fallback path: if the non-Windows Qt Network path is not reliable on all targets,
add a small optional dependency (`libsoup`) in a separate commit with packaging
updates.

Rules:

- Never block the GTK main loop.
- Set a short timeout.
- Send a clear `User-Agent: VertexNote/{version}`.
- Treat update checks as best-effort; failures should not affect note-taking.

## Settings

Add these settings after the dialog exists:

- `vertexNoteUpdateChecksEnabled`, default `true`.
- `vertexNoteLastUpdateCheck`, ISO timestamp.
- `vertexNoteSkippedVersion`, optional semver string.

Automatic checks should run at most once per day and only after startup is complete.

## Security And Compatibility

- Do not execute downloaded installers from inside the app in the first implementation.
- Use HTTPS only.
- Show the canonical GitHub release URL before opening it.
- Keep semantic-release as the single source of release notes.
- Keep the update feature independent from `.xopp` document loading/saving.

## Implementation Phases

1. Version parser/comparator with tests.
2. ReleaseInfo JSON parser with fixture tests.
3. ReleaseChecker async fetch.
4. GTK UpdateDialog and Help menu action.
5. Settings for automatic checks and skipped versions.
